# CUDA 生命周期探针 v2：原生校准失败

冻结并重新编译作者 v2 探针，在 Starpub 原生运行完整四卡基线时失败，探针和校验器均退出 1。**没有启动内部 guest，也没有 Docker 生命周期通过结论。** 七个记录的命令进程组为空，源码、二进制及输入哈希未变；`normal_shutdown=false` 对应未创建实例，不能称为正常 guest 关机。

校准前，直接参数夹具完成 45 项；Python 套件报告 46 项、其中 **1 项跳过**，不能记成 46 项通过。跳过原因是 owner 将参数夹具输出命名为 `build/args-fixture`，而 Python 测试寻找 `build/cuda-lifecycle-args-fixture`；夹具另行直接运行成功。下轮会统一文件名。

原始基线暴露的探针缺陷包括：

- PTX 缺少浮点寄存器声明和 store 的 `.f32` 类型；四张卡的 module load 均返回 218。它并未实际沿用之前已运行成功的完整 PTX。
- 四条 inventory JSON 缺少 `uuid` 键，四条 child JSON 提前关闭对象，共八条无法解析。
- solo 阶段在创建上下文前调用内存查询，返回 201。
- solo 清理代码用 destroy 返回值覆盖 unload 返回值；请求的字节数也被记为已经检查的字节数，即便没有完成计算。这些记录不能作为完成证据。

Python 校验器正确拒绝本轮数据，但之前的合成模型测试没有覆盖这些真实 C 输出和 PTX 缺陷。修正任务要求直接调用生产输出函数生成成功/失败夹具、保留独立清理返回值，并沿用已验证的 PTX；不能删除失败阶段或放宽验收。原生重新校准通过后才进入内部 Docker 对照。

本目录完整保留失败源码、日志及校验原因；`recheck.py` 核验失败范围、跳过计数和清理记录，不修写原始 JSON。
