# GPU 生命周期：第二次原生校准仍未通过

本轮冻结了代理开发中的 v3 源码，修正上一轮的 PTX、JSON、上下文顺序和实际完成字节统计问题后进行原生校准。CUDA 探针返回 0，但独立检查器返回 1：**四个子进程的完整报告接收时间戳均为 `-1`**，不能据此通过并发生命周期验收。没有启动内部 Docker。

实际输出为 30 条有效 JSON 记录，包括四卡清单、12 条独立/线程/子进程工作记录和 12 个有向卡间访问及传输记录。CUDA 计算与传输记录没有结果不匹配，12 对原生卡间访问均可用；这些事实不替代缺失的握手时序证据。

原因在新加入的失败状态初始化：`firstbyte_ns` 改成 `-1`，接收循环仍使用 `!firstbyte_ns` 判断是否尚未记录，因此不会写入实际接收时刻。该字段历史名称虽叫 firstbyte，代码实际在收到换行、完整报告到齐时赋值。后续单独的新运行将使用 `< 0` 条件；本目录保留原始失败数据，不补写或推测时间戳。

严格编译、45 项参数 fixture 检查通过。Python 检查共 62 项，**56 通过、6 跳过**；快照时真实 C 输出 fixture 尚未交付，六项依赖它的检查没有运行，不计通过。7 个命令组已清空，源码、输入和驱动库哈希未变。外层运行状态为失败，`normal_shutdown=false` 是因为原生校准未通过、没有创建 VM，并非发生一次 guest 异常关机。

`freeze.json` 标明这是一份开发中源码的独立快照。运行 `python3 recheck.py` 会重新调用冻结的独立检查器，确认仍拒绝同样四个缺失时间戳，并核对日志、源码和进程清理记录。完整 GPU 生命周期、标准 `--gpus` 接入、稳定性和性能仍未完成。
