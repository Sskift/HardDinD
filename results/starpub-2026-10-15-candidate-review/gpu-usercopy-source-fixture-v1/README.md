# GPU 用户复制候选的确定性交错检查

本记录是 **macOS arm64 上的轻量源码夹具**，不是 Starpub、Linux guest 或 GPU 的执行结果。远端连接中断期间，用它补足候选审查中的并发验证缺口；没有在本机编译内核或运行 GPU 工作负载。

输入为 [生命周期 v8](../gpu-cuda-lifecycle-v8/README.md) 的冻结 `gpu.c`，SHA256 `e6ce7e45b3d018cce104825e9b1807cf1c02a2bbe54e4a8ed104e276f0ad341f`。执行器原样提取五个转发、引用和嵌套指针处理函数。模型使用的 GPU 操作号和影子页数量来自同一快照的头文件；用户访问、分配器、FD 表和 worker 是替身。

`local-darwin.json` 记录 Apple clang 21.0.0 的实际编译与执行：

- 正向：204 次断言，0 失败，退出码 0。
- 注入缓冲区别名的负对照：24 次断言，恰好 1 次预期失败，退出码 1；检出 A 在解锁后输出复制时读到了 B 的结果。
- 编译与两次运行均没有超时，命令结束时对应进程组为空。

交错检查用条件变量确定次序，不依靠循环次数或概率撞到竞态。FD 检查执行候选的实际 `gpu_hold_fd` 和 `gpu_put_holds`：在 worker 使用期间关闭并复用相同的 guest FD，确认原 host FD 的引用仍有效，输出恢复 guest FD，原文件最终只释放一次。失败路径另外检查私有缓冲区和已获取的引用是否释放。

完整覆盖范围与复现命令见 [夹具说明](../../../tests/gpu_usercopy/README.md)。本结果不证明真实缺页、VFS、OOM、事件分配、完整 ioctl ABI 或长期并发通过，也不确认同进程第二个 CUDA context 返回 304 的原因。v8 的真实 GPU 失败保持不变，锁顺序补丁仍未加入正式构建序列。
