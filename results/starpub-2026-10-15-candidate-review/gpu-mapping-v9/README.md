# 旧 GPU 后端设备节点回退验证

使用与 v8 **逐字节相同的诊断脚本**，切换回此前已验证控制功能的系统特性内核 `9192f196143242aab3dfacc2966d7bcc605db9cc0caadfe68b09a76cb42b557e`。该旧后端只提供 `harddind-nvidia*` 控制/卡节点，并不提供 UVM。

实际 Docker 操作先确认标准节点缺失，再成功回退到 `/dev/harddind-nvidia*`。两个 UVM 路径均如实报告缺失。原生前后四卡计算、传输和校验通过；内部 CUDA 仍按旧后端能力边界失败，没有把回退路径可用计作 GPU 完整通过。

客体正常停止，输入和驱动库哈希未变。**16 条命令及客体/网络共 18 个进程组**均独立核实为空。缺失节点的非零退出保留在命令账本中，只有对应的明确缺失错误允许走回退，其他失败不被吞掉。

本次只验证新诊断脚本对旧后端的兼容性，不是性能比较。原始证据联合复核见 [v7 说明](../gpu-mapping-v7/README.md)，同一新内核在标准节点上的后续缺口见 [v8](../gpu-mapping-v8/README.md)；所有内部 CUDA 运行仍为失败。
