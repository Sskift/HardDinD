# 修正 raw ptrace 观测后的 FP 矩阵

探针 v7 重新从真实 `ptrace(PTRACE_SETREGSET)` 调用读取返回值、errno 和调用后的 `iovec.iov_len`。此前 v6 的辅助函数提前返回，错误地把未改写的本地零值记成内核返回的长度；`-errno` 也不能称为原始系统调用返回值。旧报告保留，撤回说明见 `author-report.md`。

本轮 owner 在 Starpub 重新严格编译，运行独立 raw-regset 检查、原生 15 项及 12 种 guest 配置各 15 项诊断检查，全部通过且无跳过。所有 17 个命令进程组正常退出并为空，源码、镜像和两个内核哈希未变。只有探针变化，未重建或改动 FP 内核候选。

本轮实际观测：

| 请求 | 原生 raw rc / errno / 调用后长度 | 12 组 guest 的结果 |
| --- | --- | --- |
| FX28 | -1 / 22 / 28 | -1 / 22 / 28，拒绝且状态不变 |
| FX32 | -1 / 22 / 32 | 0 / 0 / 32，接受前缀并保持其余字节 |
| FX256 | -1 / 22 / 256 | 0 / 0 / 256，接受前缀并保持其余字节 |
| XS172 | -1 / 22 / 172 | -1 / 22 / 172，拒绝且状态不变 |
| XS176 | -1 / 14 / 176 | 0 / 0 / 176，接受前缀并保持其余字节 |
| XS520 | -1 / 14 / 520 | 0 / 0 / 520，接受前缀并保持其余字节 |

因此，诊断测试通过不等于原生 ABI 相同。短前缀的接受差异在 eager、lazy 关闭及 lazy 开启各配置中均存在。探针还校验信号恢复、线程唤醒后的 FP/SIMD 内容、fork 继承值、exec 重置和寄存器生命周期；core note、无效 XSTATE 镜像及完整应用兼容性仍未覆盖。此前 lazy FP 的性能回归没有因本轮正确性结果消失，候选未提升为默认路径。

探针源码 SHA-256：`d9774a5238af4736490063c582faa8e1bc613c98507bc4e5ed2f6102b1550789`；同一原生/guest 二进制：`31566981ad31367c4fa3eab7fb69384580296b452774626c19f59692c25f8dec`。`recheck.py` 从原始输出重建 13 组结果，逐项验证六类原始返回记录及清理证据。
