# CPU 探针增加实际工作量记录

新探针在原有忙循环中记录每个线程完成的块数，每块仍为原来的 1024 次依赖整数运算，同时保留最终结果。分析器使用模 2⁶⁴ 的仿射递推独立重算结果，拒绝计数、线程编号或结果不符的记录。旧探针没有计数时明确记录为 `not_tested`，不从 CPU 时钟推算实际完成的工作。

这项记录用于区分调度计量变化和程序实际执行量。CPU 限额的原有判定公式、时窗和阈值保持不变；计数与结果一致仅证明本轮工作量记录自洽，不代表完整性能通过。新探针与旧二进制不同，后续性能对照必须在各条件下使用同一个新二进制。

Starpub 原生验证完成：静态编译和自检成功，75 项 Python/Linux 检查通过且无跳过，四线程执行约一秒后共报告 1,484,589 个工作块，四个最终结果均重算一致。该次短运行用于验证计数功能，不能当作性能基准。输入哈希未变，四个受控进程组在结束后独立复查为空。

构建和执行等待上一轮 CPU 时钟负载对照完全结束后才开始，持有全局独占锁，限制到四个宿主 CPU；锁内总时长约 2.93 秒。此次尚未在内部 Docker 运行新探针，`guest_verification` 保留 `not_tested`。

源码、编译命令、原始 JSONL 和测试输出在本目录；可执行文件仅记录远端 SHA256。离线复核：

```sh
python3 results/starpub-2026-10-15-candidate-review/cpu-work-count-v1/recheck.py
```
