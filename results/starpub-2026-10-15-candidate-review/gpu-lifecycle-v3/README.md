# 四卡原生生命周期基线 v3：失败，尚不能用于内部 GPU 验收

2026-10-14 21:50 UTC 在 Starpub 上运行同机原生四卡 A100 探针，进程正常结束但返回 **1**。这次实测发现了探针的上下文管理和报告协议错误；不能据此判定内部 GPU 后端，也不能把它记为已通过的原生基线。内部容器 GPU 和性能均未测。

本轮先修复了两个报告解析缺陷，保留修改前后实测反例：

- 163 字节的合法周期记录原来被 160 字节缓冲区截断，校验和 `4294967295` 被误读成 `429496`，解析仍返回成功。修复后完整保留。
- 原来接受 `4294967296` 的有符号、无符号越界以及多余尾字段。修复后验证长度、字段数量和转换前的整数范围，三个反例均拒绝。

固定版本 C 源码通过严格编译和独立 ASAN/UBSAN 主机夹具。Python 测试实际为 **48 通过、2 跳过**，跳过项因为其预期路径下没有夹具二进制/日志；不能算通过。`OWNER-ACTUAL-NATIVE-V3.md` 是当时发给作者的原始交接，里面“50 Python tests passed”的表述不准确，以保存的 `checker-tests.stderr.gz` 和本说明为准。独立夹具运行成功并不会自动补成这两个跳过项的通过记录。

原生运行具体暴露了四处问题：

1. 四个共享上下文线程均在 `cuCtxAttach` 返回 201。调用发生在线程绑定当前上下文之前，后续周期没有执行。
2. 四个新执行的子进程各自正常退出、分配/释放均为 6 且计算误差为 0，但父进程拒绝其报告。实际报文带换行，而夹具预先去掉了换行，掩盖了最后一个周期字段的解析失败。
3. 子进程周期协议没有传送开始/结束时间，解析后这些字段为 0，无法验证周期时序。
4. 子进程开始门设在 CUDA 初始化之前；实际计算窗口交集为 **−74.022055 ms**，没有证明四个子进程同时计算。修复需要初始化完成后的就绪握手和有界清理，不能去掉并发判据。

`owner-report.json` 保留原始失败状态；因为原生命令失败，原流程没有执行运行后 GPU 清单和输入校验。补充的 `owner-input-audit.json` 独立验证源码、探针二进制和驱动库未改变，没有改写原报告。`owner-cleanup-audit.json` 证明全部 **10 个进程组为空**，无超时或强制清理。运行后 GPU 清单仍记为未执行。

`author-v2/` 是解析修复前的冻结源码，根目录 `src/` 是实测 v3 源码。`original_protocol_regression.c` 保留当时指向远端冻结 v2 源码的绝对路径，其内容由 v2 清单校验；重新编译该对照时需要把这个引用重定位到本归档的 `author-v2/src/cuda_lifecycle_probe.c`。没有收录 Linux 二进制、Python 字节码或 CUDA 缓存；这里是源码与诊断证据归档，不是完整可直接启动的环境。

在仓库根目录执行以下命令可核对归档哈希、原始反例、输入/清理审计，并用冻结检查器重新解析四卡原生失败：

```sh
python3 results/starpub-2026-10-15-candidate-review/gpu-lifecycle-v3/recheck.py
```

这些候选源码尚未合入主运行路径。下一次实测必须先修复上下文绑定、真实报文解析、周期时间传输和子进程就绪同步，再重新通过原生基线，之后才进入内部容器比较。
