# IPv6 分片：内部 Docker 端口发布复验

Starpub 原有无特权容器内，真实 UML + Docker 的 **21 项发布端口检查全部通过**。以前从 1453 字节起失败的 IPv6 UDP 已能完成大报文双向传输和逐字节校验。本轮使用的网络后端就是 [原生及 sanitizer 复验](../publish-fragment-native-v2/README.md) 中的普通构建二进制。

覆盖 IPv4/IPv6 TCP/UDP 发布，多个外层地址共用同一端口，别名随端口创建与释放，失败启动回滚，默认及自定义 bridge 的冲突重试，多端口回滚，通配与具体地址双向冲突，显式转发归属，临时端口、范围、`-P`、四个并发发布，以及整个实例正常关机、重启后的端口恢复。

- 121 条实际 Docker/实例控制命令均达到预期退出结果，其中 9 条冲突或失败场景预期返回非零，不能描述为“所有命令返回 0”。
- 140 次记录的数据传输全部校验一致。IPv6 UDP 在 1、1200、1452、1453、1456、8000、60000、65507 字节各有两次成功记录；IPv6 TCP 覆盖 64 KiB。
- 两次实例运行都正常退出，未强制关机；随后独立复查 128 个进程组全部为空。源码、内核、基础磁盘及被记录输入的哈希保持不变。

实际范围是外层 IPv6 回环地址发布到内部默认 IPv4 bridge 容器，由 Docker 自带 proxy 转接。没有测试外部非回环 IPv6 可达性、完整 IPv6 bridge/扩展首部/RFC 一致性、Swarm ingress、异常断电恢复，也没有比较网络性能。不能把这 21 项通过扩展成完整 Docker 或性能目标完成。

外层汇总脚本在实际测试结束后错误读取 `cleanup['pgid']`；真实字段为 `process_group`，因此原始 `owner-status.json` 保留 `exit_code=1` 和 `KeyError`。实际测试脚本返回 0，`runtime/pubfrag1.json` 的 21 项结果、正常关机记录均已产生。`post-run-audit.py` 未重写旧记录，而是读取正确字段，重新检查所有命令组、两轮 VM 进程组、源码与磁盘哈希，生成独立的 `post-run-audit.json`。运行 `python3 recheck.py` 会同时核对这两个层次。

基础磁盘沿用此前经过构建和校验的 Moby 29.8.2 发布端口候选，新增运行使用独立实例与 COW 磁盘。没有连接宿主 Docker socket、增加宿主权限或修改外层安全策略，未使用 `/root/udock`。源码快照保留测试时版本；其中旧的其他实验代码不代表本轮重新测试，也不会整体覆盖当前主线。
