# 纯 CPU 首次匿名内存写入对照

这轮不调用 CUDA，也未向内部容器传入 GPU 设备。每次新建 1、4、16 MiB 私有匿名映射，每页写一个字节，校验后立即再写一次并校验；每种尺寸重复八次。原生前、内部 Docker、原生后三阶段各三个进程，共 **216 条冷/热配对记录全部通过**。13 条命令成功，16 个记录的进程组为空，实例正常关闭，输入哈希未变。

采用整数 `CLOCK_MONOTONIC` 计时，`getrusage(RUSAGE_SELF)` 在计时区间外读取次要/主要缺页计数。每个格子的中位数来自同一阶段、同一尺寸的 24 次独立新映射；不混合运行前后的原生对照。

| 映射尺寸 | 原生前冷写 ms | Docker 冷写 ms | 原生后冷写 ms | 冷写次要缺页中位数 |
| --- | ---: | ---: | ---: | ---: |
| 1 MiB | 0.413 | 5.675 | 0.576 | 256 |
| 4 MiB | 2.041 | 22.272 | 2.569 | 1024 |
| 16 MiB | 9.000 | 82.979 | 11.348 | 4096 |

所有记录的热写次要缺页、冷写和热写的主要缺页均为零。4 MiB 热写中位数为原生前 8.3 µs、内部 28.4 µs、原生后 8.8 µs。个别原生冷写记录比页数多一次次要缺页，未从结果中删除。计数分别来自所在内核的进程记账，不能把 guest 次要缺页当作宿主某一个信号或系统调用的计数。

这证明不经过 CUDA 的匿名内存首次触碰本身也有明显额外成本，与 GPU 冷输出回传的定位方向一致。它**没有**直接量出每次缺页的宿主调度、信号、futex 或映射提交耗时，也没有证明 GPU 回传的全部差距都由缺页造成。下一步需要沿 UML 缺页路径计数和审查，减少实际处理成本；提前写内存只会移动工作，不能用来宣称应用性能已经一致。

这是按页跨步写入的诊断，不是连续复制带宽测试；无自定通过阈值，不代替完整应用性能验收。原始记录、源码和 `recheck.py` 一并保留。
