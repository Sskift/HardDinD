这轮实际运行完成，所有内容校验通过，但**不能用于性能结论**。一个远端代理把 GPU 内核构建锁写成了 `/kernel-build.lock`，绕过实验使用的 `/root/harddind-rebuild/kernel-build.lock`。构建与原生前置参照、原内核、候选关闭阶段重叠，直到候选开启阶段的导入过程中才完成清理。源码、进程身份、时间范围和强制清理记录均保留；没有将这轮数据当成有效的加速证据。

固定的原内核为 `b8a58b855edb…`，候选为作者 build6 的 `9a253e98116c…`。候选补丁通过普通匿名缺页路径预先处理一个对齐窗口，默认关闭；本轮开启值为 4，即最多 16 页。两者配置逐字节相同，父控制器重新应用补丁后，36 个源文件与候选构建树相同。父控制器没有独立重建这一候选内核。计数器关闭时仍有时钟读取成本，已经明确记录为候选缺陷。

在同一静态 `cpu-touch-probe` 上顺序运行原生前置、原内核、候选关闭、候选开启、候选再次关闭、原生后置六组。每组三次进程运行，每次分别对 1、4、16 MiB 做八次冷写、热写及内容校验，共 432 条记录。内部 Docker 保持 4 vCPU 和既有异步 GPU 配置；本探针不执行 GPU 工作，因此不构成 GPU 回归通过。
