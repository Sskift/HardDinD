# 运算计数的周期别名校验

独立审查发现，首版工作量校验允许 `work_blocks` 达到 2⁶⁴−1，但递推结果每 2⁵⁵ 个块重复。将真实记录中一个线程的计数加上 2⁵⁵，保持结果不变，旧校验器仍会通过并产生虚假的巨大吞吐。

主线现将 revision 1 的可验证范围收紧为 `0 <= work_blocks < 2**55`。这是递推的精确周期边界，不是性能阈值。每块的变换为 `F(x) = A*x+B mod 2**64`，其中 `A=12255457568021647361`、`B=6762530292265691648`。`A−1` 含 12 个因子 2，`B` 含 9 个；任意种子的单块增量都恰含 9 个因子 2。由于 `A ≡ 1 mod 4`，n 项几何和含的因子 2 数量为 `v₂(n)`，首次回到原值要求 n 为 2⁵⁵ 的倍数，因此首个周期内的计数才唯一。

Starpub 执行五项定向算术回归，无失败或跳过，覆盖不同种子与计数的逐步递推对照、缺失计数、错误结果、错误协议及周期别名。此前实际四线程记录用修正版重算仍完全一致，而同一原始记录加上 2⁵⁵ 后被拒绝。这是校验器缺陷修复，不表示已测运行的计数错误，也不证明内部 Docker 或整体性能通过。

原始版本与实验记录保留在 `cpu-work-count-v1`，本目录保存修正后的校验器、测试源码、真实原始记录和测试输出。仅执行轻量 Python 校验，没有重新运行忙负载。
