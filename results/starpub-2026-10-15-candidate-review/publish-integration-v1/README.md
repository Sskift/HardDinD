# IPv6 与发布端口改动集成检查

在 [实际 Docker 21 项检查通过并独立清理复核](../publish-fragment-docker-v1/README.md) 后，将相关网络源码、固定 Moby 补丁、guest 地址配置及固定 libslirp 补丁合入当前主线工作区，并把该工作区源码复制到 Starpub 独立目录重新构建。

集成时保留当前 GPU、内核与文件系统改动，未整体覆盖旧候选仓库。额外恢复了 `build-network.sh` 对静态 `network-probe` 的构建，避免干净工作目录缺少探针；端口验证测试保留原有非法端口用例。新增 `make publish-tests` 入口可构建并运行原生网络后端测试。

- 新目录中的固定 libslirp/网络后端构建成功，其自带原生分片检查通过。
- `make check` 共 219 项：206 通过、13 跳过。13 项是本目录未构建的 GPU 生命周期、协议及 OS-event 探针/fixture 相关检查，不计为 GPU 验收通过。
- 29 项真实网络后端测试通过，无跳过。
- 新构建的静态网络探针读取到回环 IPv4 和 IPv6 地址。
- 4 个命令组清空；189 个源码输入前后哈希一致。

实际 Docker 实测使用上一轮的二进制；本轮对同一被测网络实现重新构建，增加构建入口和测试覆盖修复，没有另一次 Docker 运行或性能样本。完整功能、标准 GPU 参数、并发生命周期、共享文件语义和性能验收仍未完成。

运行 `python3 recheck.py` 可校验保存的日志、源码、关联实测报告、跳过计数及进程清理记录。
