# GPU 映射 v6：设备注册恢复，旧控制语义出现回归

这是候选补丁的失败证据，不是完整 GPU 验收。设备别名改为不同设备号后，内部客体成功创建 GPU worker、执行 434 次设备 ioctl，并通过 11 个普通功能检查。但同机原生前后对照均为 31/31 时，客体仅 **24/31** 与原生一致。

七个差异为 `size_zero`、`size_short`、`size_long`、`size_max`、`null_size_zero`、`client_zero_bad_size`、`finn_bad_size`。候选补丁在 `gpu_rm_control` 中无条件检查声明长度，提前返回 `EOPNOTSUPP`，丢失了已在 0027 验证的驱动校验顺序和 RM 状态：原生通常返回状态 31，无效 client 优先返回状态 35。修复应恢复已知固定结构命令的驱动校验，仍只预先访问有界的规范结构大小，不能按不可信声明长度扩大访问。

所有阶段正常结束，无超时或强制清理。独立审计确认 4 个运行进程组和 1 个重建进程组均为空。因为控制回归未通过，显存分配回归和 CUDA 均未运行。
