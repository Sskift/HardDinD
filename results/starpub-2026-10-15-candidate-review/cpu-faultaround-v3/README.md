# 关闭计数器开销修正后的同机对照

这轮优先验证非 GPU 的内存执行开销。**修正关闭状态下的计时调用后，没有观察到稳定加速；此前候选的回退不能只归因于多读了时钟。** 新候选仍未合入默认构建，也没有完整 Docker、内存语义或性能验收通过结论。

固定同一探针和镜像，按原生、原内核、旧候选关闭、新候选关闭、新候选开启、新候选关闭、旧候选关闭、原生的顺序执行。每阶段三次独立进程，每次对 1、4、16 MiB 各做八次首次写入、热写和内容校验；表内是每个规模 24 次测量的中位数，单位 ms：

| 阶段 | 1 MiB 冷写 | 4 MiB 冷写 | 16 MiB 冷写 |
| --- | ---: | ---: | ---: |
| 原生前置参照 | 0.431 | 1.757 | 8.810 |
| 原内核 | 3.951 | 15.907 | 51.137 |
| 旧候选关闭 | 3.974 | 12.896 | 49.097 |
| 新候选关闭 | 4.597 | 16.984 | 70.021 |
| 新候选开启，16 页窗口 | 2.103 | 9.631 | 32.178 |
| 新候选再次关闭 | 3.404 | 12.228 | 58.125 |
| 旧候选再次关闭 | 3.225 | 11.780 | 47.218 |
| 原生后置参照 | 0.470 | 1.883 | 10.510 |

新候选的 16 MiB 关闭状态在前后两次比较中都比旧候选慢；其他规模也有顺序和波动影响。因此不能将“删除额外时钟调用”写成已获得速度收益，更不能断言这轮找到了回退的唯一原因。窗口开启仍比相邻关闭阶段快，但 4 MiB 约需原生的 5.1–5.5 倍时间，16 MiB 约需 3.1–3.7 倍；没有性能一致结论。所有阶段的热写新增 minor fault 均为 0，冷写仍按实际页数记账。

此次源码变化只在候选的 `0030`：先判断计数开关，再读时钟；关闭时恢复原来的 map/unmap 操作；开启时统一用宿主单调时钟，明确 `run_ns` 包含用户执行时间。匿名窗口的 `0029` 与旧候选逐字节相同。新补丁 SHA256 为 `5692ba911c52b88f62be069ad11ed6afac4291529065f6ecae004288adf1ccc1`，新内核为 `540c903a0da8fffe6424adafa1ae4e8510470763a5e0693e4d6643aece47c4b2`。父控制器从固定基线重新应用补丁，36 个源文件与实际构建树一致，配置与基线逐字节一致；内核为作者构建，父控制器未独立重建。

运行保持 4 vCPU、原有网络和基线启动参数，没有执行 GPU 计算。576 条记录全部完成内容校验，48 个命令退出码为 0，六个 guest 正常关机，66 个受控进程组在结束后独立复核为空。原生阶段持有全局独占锁，guest 阶段持有共享锁，排除遵守协议的构建；没有并行 owner 性能实验。不声称排除了同机其他负载或只读源码审查的影响。本轮是一次顺序微基准，原生参照本身也有变化。

作者的主机语义测试结果仅作为交付材料保留，其中 userfaultfd 和 memcg 检查有跳过。它们不是本轮内部容器的语义通过证据。窗口仍会改变提前驻留、RSS、`mincore()` 和 OOM 时机，完整语义需要继续验证。

`archive-sha256.json` 固定归档的源码、补丁、配置、控制器、原始日志和报告。内核、磁盘、镜像与两个作者测试可执行文件保留远端输入哈希，不把未归档二进制称为离线重新验证过。重放检查会重新应用补丁、重算 576 条原始记录、核对所有命令及清理结果：
