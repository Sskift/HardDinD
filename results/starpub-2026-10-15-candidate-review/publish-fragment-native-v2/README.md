# IPv6 分片候选：重新构建与原生复验

Starpub 上使用冻结的最终发布候选和修正后的独立测试重新构建。普通构建、ASAN/UBSAN 构建分别通过 **108 项独立分片检查、29 项网络后端测试**。本轮没有启动内部 Docker，也没有测量性能。

| 同一套测试源码，分别链接的实现 | 普通构建 | ASAN/UBSAN |
| --- | --- | --- |
| 最终候选 | 108 项通过，无跳过 | 108 项通过，无跳过 |
| 旧错误实现反例 | 102 项中 20 项失败，触发 17 个缺陷条件 | 102 项中 20 项失败，触发 17 个缺陷条件 |
| 最终候选网络后端 Python 测试 | 29 项通过，无跳过 | 29 项通过，无跳过 |

旧实现因队列回收失败，后续 6 项依赖该状态的填充检查明确跳过，不能算通过。负对照返回 1 是预期的缺陷检出结果。候选对应步骤全部执行。

上一轮的 [4/75 失败](../publish-fragment-native-v1/README.md) 保留。独立复核确认两类测试错误：直接要求内部过期时间是未截断的 64 位值；以及新队列刚创建便要求立即过期。本轮按实际生产的 32 位时钟调用约定检查行为，验证过期前 1 ms 仍存活、60 秒边界回收、跨回绕、不同创建时间、回收后重新填满以及新队列自己的完整存活时间。它没有验证假想的其他时钟 ABI。

每个构建均重新解包固定版 libslirp 4.6.1，应用 IPv6 补丁和固定 Ubuntu 安全补丁，编译全部 32 个 C 源文件。独立测试使用新输出目录，不复用旧目标文件。普通与 sanitizer 构建的源文件哈希一致；普通网络后端 SHA-256 为 `70992833032be268d7e7876c8390a165c86105e9c93623e646ca36c04a7ab78f`。安全补丁与仓库保存的固定 Debian 源包成员逐字节一致；分片测试本身不覆盖该安全补丁的 TCP 紧急数据行为。

12 个命令进程组均已清空，源码与独立测试输入前后哈希一致。Python 测试仍有未关闭读取管道的 `ResourceWarning`，原始输出保留；未发现 ASAN/UBSAN 报错，进程清理另有实际记录。仅有进程清理通过不能消除这些 Python 资源管理警告。

`independent/REPORT.md` 是独立代理交付原文。其中“同一 binary”和对假想 64 位实现的推广不作为结论采用：实际是同一测试源码分别链接，且检查当前生产时钟 ABI。GLib 头文件等完整输入记录在运行清单中，本目录保存被测源文件、测试和日志，不保存 ELF、静态库及整套开发包。

运行 `python3 recheck.py` 可重新校验归档完整性、结果计数、负对照、源码及安全补丁身份和清理证据。完整 IPv6、内部 Docker 端口生命周期、异常恢复和性能仍需要后续实测。
