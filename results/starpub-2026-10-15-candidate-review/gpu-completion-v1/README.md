# GPU 同步到异步交接竞态修复

仅修改 UML `stub_signal_interrupt` 的完成标志交接顺序，内核其余 32 个跟踪文件及配置不变。修复内核 SHA256 为 `b8a58b855edb97bb8cf06bd99ef26fb7a63f08e0e38ba07fa1dcb8f915c1b502`，独立补丁为 `0028-um-gpu-completion-ownership.patch`，SHA256 `8a5288aeb8e3bf987269d4d3f0addf0497b9db3c890b979913bbd29463ec728a`。

旧代码存在以下可成立的交错：

1. worker 完成同步映射，发布 `FUTEX_IN_KERN`，允许调用者继续。
2. 调用者准备下一条异步 ioctl，把结果设为默认 `-EIO`，设置 `gpu_async=1` 并提交。
3. 旧同步操作的 worker 帧此时才读取并清除 `gpu_async`，将新请求的标志当成自己的，提前发送完成通知。
4. 调用者可能读到尚未更新的 EIO 和原始头，并开始错误清理；新 ioctl 仍可能执行。

修复在发布空闲状态**之前**领取当前批次的异步标志到局部变量，仍在发布空闲状态**之后**发送已经领取的通知。这样既不偷取下一批请求的标志，也不让下一次交接被上一帧覆盖。保留异步可调度等待，没有增加休眠或重试来掩盖错误。

实际结果：同 v2 的八组顺序（日志、无追踪、两者、strace、strace、两者、无追踪、日志），开启异步等待，**8/8 个内部 Docker 容器完成四卡真实计算、双向传输及每卡 1,048,576 个元素的精确校验**。原生前后各四卡通过，实例正常关机，29 个运行进程组及 3 个构建验证进程组为空，输入未变。

此前同条件旧内核为 4/8 完成，出现 CUDA 304、999 和退出码 139；关闭异步等待的旧内核对照为 8/8。原始反例分别保留于 [v2](../gpu-instrumentation-v2/README.md) 和 [v3](../gpu-instrumentation-v3/README.md)。本次有限运行支持修复上述竞态，**不能证明所有 GPU 错误已解决、完整生命周期已覆盖或性能已经一致**。独立协议审查仍在进行。

`python3 recheck.py` 验证只修改一个源文件、补丁精确重放、构建前后哈希和全部实际计算记录。[完整序列复现和控制/分配回归](../gpu-completion-integration-v2/README.md) 另行记录。后续仍需无追踪重复性能测量、多进程/线程、显存生命周期、peer 传输及标准 `--gpus` 接入。
