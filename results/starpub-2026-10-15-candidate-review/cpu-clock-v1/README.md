# CPU 调度时钟候选：无外层采样器的关闭／开启对照

**旧内核再次出现限额组长停顿，但本轮不能把它的消失归因于开启高精度调度时钟。** 同一候选的关闭、开启、再次开启、再次关闭都未复现同等量级的停顿。候选没有默认合入，CPU 限制与完整性能仍未验收。

使用此前冻结的 witness 二进制，每个观察进程做 60 次采样、目标间隔 100 ms，每次依次读 `cpu.max`、`cpu.stat`、再次读 `cpu.max`、读 `/proc/stat`、读取进程 CPU 时钟。内部分别通过实际 `docker run --cpus 0.5` 和无限额容器执行，所有样本均核对实际 `cpu.max`。本轮保持 4 vCPU，没有忙线程、strace 或外层 10 ms 采样器。该程序仍有自身观测成本，不称为零开销。

以下是单次五阶段采样的耗时，单位 ms；每个单元来自 60 次采样：

| 阶段 | 限额组中位数 | 限额组最长 | 无限额组中位数 | 无限额组最长 |
| --- | ---: | ---: | ---: | ---: |
| 原内核 | 0.306 | 182.786 | 0.236 | 2.808 |
| 候选关闭 | 0.239 | 1.934 | 0.233 | 1.660 |
| 候选开启，第一次 | 0.267 | 2.894 | 0.352 | 2.132 |
| 候选开启，第二次 | 0.267 | 2.175 | 0.248 | 1.679 |
| 候选再次关闭 | 0.356 | 2.968 | 0.255 | 2.550 |

这些数据没有给出同一候选开关之间的稳定收益，有限次数未复现也不证明长停顿已经消失。旧内核与候选关闭之间还存在构建和诊断代码差别；仅凭本轮不能确定导致差异的因素。后续需要忙线程、份额反转、限额更新及更长重复对照，分别验证调度计量、真实执行量和命令响应时间。

外层原生前后各执行了一次相同 witness：中位数为 0.432、0.410 ms，最长为 0.637、0.785 ms。它们使用现有外层 cgroup，没有对应的原生 0.5 CPU 限额组；宿主与 guest 的 `/proc/stat` 内容和 CPU 拓扑也不同。因此这些参照不能用于宣称 guest 比原生快，或将内部资源控制判为与原生一致。

本轮实际完成 720 次采样、3600 个阶段，32 个命令退出码均为 0，五个 guest 正常关机。47 个受控进程组在结束后独立核对为空，输入、源文件及外部固定程序/磁盘哈希不变。串行运行，原生持有全局独占锁，guest 持有共享锁；没有并行 owner 性能实验，不声称排除了同机其他负载。

候选为作者 v5 SMP 内核 `5b3d3c507a00cd6c56dfb0dfec06f07b62633c4e9a487e5905ab960a105c10b0`，基线为此前 CPU 限制实验内核 `fb5e56e48240f96a997aa0f1d234992f128d23dd428eb8256dfccccc4d217fca`。两边配置逐字节相同，SHA256 为 `bd17febf02803c6b966948829fa25d3bfc85a354ac8746afaa3422a8ec65549b`，保留 SMP、cpuset、bridge、IPVS、virtiofs 等功能。父控制器从冻结的 33 文件基线和固定上游 `fair.c` 重新应用两个补丁，35 个结果文件与实际构建源码一致；父控制器未独立重建内核。

高精度模式采用宿主单调墙钟，改变调度和计量粒度，但没有扣除宿主调度等待时间。参数默认关闭，time-travel 路径本轮没有运行。作者交付的构建说明和辅助脚本作为原始材料保存；父控制器以实际重新应用补丁及逐文件哈希核对代替其中较弱的源码检查，没有把作者报告本身作为通过依据。
