# Starpub 实测，2026-10-14

本目录是开发实验记录，**完整 Docker / 原生性能 / 内部 GPU 的总验收未通过**。

环境：外层 Linux 5.15.0-177，seccomp 开启；user/mount/network/PID namespace 探测均返回 EPERM；外层可见 72 个逻辑 CPU，CPU 配额约 36 核。GPU 为 4 张 A100 40GB，驱动 550.120。详见 `environment.json`。

候选内核：Linux 7.2.10，UML seccomp，4 个虚拟 CPU，`seccomp_spin=256`。源码补丁、构建内核与测试程序哈希均已记录。

| 微基准，3 次中位数 | 外层原生 | 候选内核 | 倍率 |
|---|---:|---:|---:|
| 10 万次 getpid 系统调用 | 0.0624 s | 0.5500 s | 8.8 |
| 100 次 fork + exec | 0.0358 s | 0.4139 s | 11.6 |
| 4 个独立计算进程 | 0.3938 s | 0.4347 s | 1.1 |
| 同一进程的 4 个计算线程 | 0.4220 s | 1.4534 s | 3.4 |

不开轮询的 seccomp 路径中，10 万次系统调用耗时 2.2389 s；轮询参数 256 将这组测试降到 0.5500 s。默认不开轮询，实验同时记录宿主 CPU 时间。这个结果不代表所有负载都提速，也没有解决同一地址空间的线程串行化。

这些是同机、相同程序哈希的诊断微基准；不是完整原生 Docker 对照，也没有相同的资源限制和完整负载覆盖。不能将多进程的 1.1 倍认定为达到“一样的性能”。

原版 Docker 29.8.2 在候选内核内运行：26 项功能测试通过，另有 GPU 测试镜像导入通过，内部 GPU 计算失败，2 项标为未测。通过项包括 BuildKit 多阶段构建、资源限制实际生效、挂载、卷、内部网络/DNS、guest 端口发布、IPv6、健康检查和信号。`docker.log` 保存原始控制台输出，`docker.json` 保存逐项结果。

GPU 外层基线在每张卡上完成 1,048,576 个元素的向量相加，全部结果逐项校验。内部 `docker run --gpus all` 返回 `failed to discover GPU vendor from CDI`，当前没有内部 GPU 后端。`native-cuda.jsonl` 不能用作内部支持 GPU 的证据。

下一步必须解决的核心实现：同一 guest 地址空间的多线程并行、NVIDIA ioctl/地址映射后端、外层网络与目录共享。Moby/containerd 后端改造尚未开始；本轮没有创建或发布 Moby fork。
