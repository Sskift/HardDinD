# 实际 Docker 工作流计时与结果校验

**五类工作流分别完成三次成功实测。它们来自修复过程中各自冻结的版本，不是同一版本的一次完整 Docker 验收；原生性能比较仍未测。** 所有开发和实测在 Starpub 的 `/root/harddind-rebuild/workflow-owner-v1` 至 `v5` 中进行，独立实例和 COW 磁盘，四个 vCPU，按顺序执行，未修改 `/root/udock`。

| 工作流 | 成功记录 | 三次完整工作流耗时，最小／中位／最大 |
| --- | --- | ---: |
| 生命周期：创建、执行、wait/stop、重启、删除 | `wf2-lifecycle` | 18.279／20.323／28.024 s |
| import/commit/save/rmi/load 与实际数据校验 | `wf2-image` | 8.971／10.802／11.084 s |
| 命名卷、两个容器读取、docker cp 内外往返 | `wf2-volume` | 7.814／9.082／12.020 s |
| BuildKit 构建、缓存重建、运行时重新计算摘要 | `wf3-build` | 8.377／8.808／10.908 s |
| 服务 DNS、实际 HTTP 内容、网络清理 | `wf5-net` | 6.218／7.160／7.473 s |

这些耗时包含校验命令和必要等待，不能解释为某一条 Docker 命令的纯延迟。生命周期中的 wait 与 stop 有意重叠。`wf3-build` 单独记录的冷构建命令中位数为 2.438 s，缓存构建为 0.913 s；没有匹配原生 Docker daemon，不能据此判断原生性能一致。宿主其他任务负载也未完全受控。

内核固定为 `fb5e56e48240f96a997aa0f1d234992f128d23dd428eb8256dfccccc4d217fca`，基础磁盘为 `0adf437833040ad84df0b47fe189b050816c356f69b6ea31b641113f34232c4c`。运行前后核对所有脚本、内核、磁盘、网络后端、CLI、加载器与所需插件哈希。rootfs 使用锁定的 Alpine 3.24.2 本地归档，各输入、命令输出、进程清理和版本源码均在归档中绑定。

修复过程保留四组失败报告：

- `wf1-lifecycle`：操作完成，但删除断言只接受首字母大写的错误文本，未接受实际的小写 `no such object`。
- `wf2-build`：文件内容、配置及缓存步骤一致，顶层索引 ID 因不同构建证明而变化。改为核对文件层与运行配置，同时在运行中的容器内重新计算文件摘要；没有关闭证明功能。
- `wf2-net`：最小 rootfs 未提供 `httpd`，服务未能持续运行，DNS/HTTP 检查失败，第三次重复未执行。改用固定 BusyBox 已提供的 `nc` HTTP 服务。初次外层诊断又因错误的 BusyBox argv[0] 名称失败，该记录保留；之后以正确名称执行同一固定二进制确认 `httpd` 缺失、`nc` 存在。
- `wf4-net`：三次 DNS 与 HTTP 校验成功，但删除检查未识别 `network NAME not found` 格式。补上准确的错误类型判定并排除 active endpoints 错误，随后 `wf5-net` 完整通过。

最终源码包含 34 项定向检查，覆盖真实子进程标准输入、输出、超时和进程组回收，失败证据判定，构建内容变化与删除错误分类。离线复核完成 9 个版本化报告、543 条命令回执，579 个受控进程组在结束后独立核对为空。工具说明见 [工作流计时](../../docs/workflow-timing.md)。v3 还统一了文本日志与 JSON 的命令计时边界，排除事后的进程组核查开销；此前版本的原始日志不重写。

`vN-evidence.tar.gz` 保存冻结源码、监督器、报告、实例日志和每条命令的原始输出，内含逐文件 SHA256。大型镜像 tar、内核、磁盘和可再生载荷仍保留在远端，归档记录其哈希；`vN-audit.json` 独立复查进程组、输入与产物，`export.json` 绑定归档。完整目标、性能一致、原生 Docker 对照和 Compose 计时均未由这批记录验收。
