# 客户端继承共享策略接入（未完成 GPU 验收）

实验补丁 `0023` 将 NVIDIA 550.120 的 `RM_CONTROL 0xd04` 接入现有 GPU worker，支持固定 12 字节、flags=0 的 `RS_SHARE_POLICY`。子结构没有嵌套指针或 FD；保持真实 RM 句柄及策略内容，由宿主驱动决定权限、参数错误和状态返回，沿用现有地址范围检查、页权限同步与指针恢复。普通构建仍不启用 GPU 实验。

补丁 SHA-256 为 `98762aefead3c35bb05473d0559d925fa1963ed435da1015cda6499a6db80372`；已实测内核为 `360c19f30cb6afce292dc4783aeff5e1ad77952e0cb360d742725c14f8e2ca9a`。这两项哈希来自 Starpub 构建及测试记录。SSH 后续在握手前中断，因此本次先保存与远端哈希完全一致的补丁及已读取的结果摘要；**完整原始日志与边界探针尚未取回，不能把此摘要当成完整、可独立复核的证据包**。原始目录清单及观察结果见 [observation-summary.json](observation-summary.json)。

| 实测 | 结果 |
| --- | --- |
| 版本查询回归 | 原生前测、关闭桥接、guest、原生后测均通过；启用阶段各 30 项检查 |
| 实际内部 Docker CUDA | 两条 `0xd04` 均 rc=0、RM status=0；下一条 `0xcb33` 对象分配返回 EOPNOTSUPP，CUDA 错误 304，未执行内部计算 |
| 同机原生 CUDA 前后测 | 两次均完成四卡计算、传输和结果校验 |
| 策略边界原生前后测 | 各 132/132 检查通过，94 条原始结果一致 |
| 策略边界 guest | 131/132 检查通过，80/94 条结果与原生一致；总结果失败 |

14 条差异分别是未知命令 `0xd0e`、八种非 12 字节尺寸、四种非零 flags，以及 fork 后使用继承 FD。特别是原生接受 `flags=0x80000000`，当前补丁仍拒绝，不能把所有非零 flags 都当成非法输入。FINN 序列化标志还会改变参数解释，扩展转发前需要按固定源码核对。

四个子进程分别重新打开设备、分配客户端、设置策略、释放客户端均成功；继承父进程 FD 的子进程在分配时返回 `EXDEV`。两者是不同情形。guest 的实际异步 worker 已核对，四阶段均正常退出且对应进程组为空。此探针验证策略设置返回和参数变化，尚未验证策略对对象共享权限的实际效果、多 UID 凭据或 CUDA IPC。

构建仍使用 `make kernel-gpu-async-experiment WORK=/root/harddind-rebuild`。真实 CUDA 可用已有 `scripts/run-gpu-cuda.py --async-wait` 继续复测；完整策略边界复现入口及源码待原始文件取回后补入。内部计算、设备映射、UVM、显存生命周期及完整 GPU/性能验收均未完成。
